2.8 Akses Manajemen (TACACS+/RADIUS)

Catatan: pada exam blueprint, 5.8 bersifat konseptual ("compare"), bukan "configure and verify". Command berikut disertakan karena berkaitan langsung dengan 2.8 (device management access via TACACS+/RADIUS) dan umum diuji dalam bentuk konfigurasi praktis/simulasi.

Perbandingan TACACS+ vs RADIUS

Aspek TACACS+ RADIUS
Transport TCP port 49 UDP port 1812 (auth) / 1813 (acct)
Enkripsi Seluruh body paket Hanya field password
Proses AAA Autentikasi & otorisasi terpisah Autentikasi & otorisasi digabung
Command authorization Didukung (per privilege level) Tidak didukung
Standar Cisco proprietary Open standard (IETF)
Umum dipakai untuk Administrasi perangkat (device admin) Akses jaringan (802.1X, VPN)

1.1.a Routers

  • Perangkat Layer 3 yang menghubungkan jaringan yang berbeda (antar subnet/network) dan meneruskan paket berdasarkan alamat IP tujuan.
  • Memelihara routing table dan memilih jalur terbaik menuju tujuan.
  • Setiap interface router berada pada broadcast domain yang terpisah (router memisahkan broadcast domain).
  • Menghubungkan LAN ke WAN/Internet.

1.1.b Layer 2 dan Layer 3 Switches

Aspek Layer 2 Switch Layer 3 Switch
Dasar forwarding MAC address (frame) MAC address dan IP address (paket)
Fungsi routing Tidak Ya (routing antar VLAN/subnet)
Broadcast domain Satu per VLAN Satu per VLAN; dapat merutekan antar VLAN
Collision domain Satu per port Satu per port
Interface Switchport Switchport, SVI, dan routed port
  • Switch memisahkan collision domain per port; hanya VLAN yang memisahkan broadcast domain.

1.1.c Next-Generation Firewalls (NGFW) dan IPS

Next-Generation Firewall (NGFW)

  • Firewall stateful + kemampuan tambahan: application visibility and control (AVC), URL filtering, advanced malware protection, inspeksi traffic terenkripsi (SSL/TLS), dan integrasi threat intelligence.
  • Mengambil keputusan berdasarkan aplikasi, user, dan konten, bukan hanya IP/port.

Intrusion Prevention System (IPS)

  • Menganalisis traffic secara real time, terpasang inline pada jalur traffic.
  • Dapat mendeteksi dan memblokir ancaman (drop paket, reset koneksi, blokir sumber), berbeda dengan IDS yang hanya mendeteksi/memberi alert.

1.1.d Access Points (AP)

  • Perangkat yang menghubungkan client wireless (Wi-Fi) ke jaringan kabel.
  • Mengubah frame 802.11 (wireless) menjadi frame 802.3 (Ethernet) dan sebaliknya.
  • Terhubung ke switch melalui kabel Ethernet (umumnya mendapat daya via PoE).

1.1.e Controllers

  • Wireless LAN Controller (WLC): mengelola banyak AP secara terpusat (konfigurasi, manajemen RF, keamanan, roaming).
  • Network controller (mis. Cisco Catalyst Center, sebelumnya DNA Center): platform manajemen terpusat untuk otomasi dan monitoring jaringan berbasis kebijakan.
  • Manfaat: manajemen terpusat, konsistensi konfigurasi, otomasi, visibilitas.

1.1.f Endpoints

  • Perangkat ujung yang menjadi sumber atau tujuan data: PC, laptop, smartphone, tablet, IP phone, printer, kamera IP, perangkat IoT.
  • Terhubung ke jaringan melalui kabel (access port) atau wireless (AP).

1.1.g Servers

  • Perangkat yang menyediakan layanan kepada client dalam jaringan.
  • Contoh: web server, file server, DNS server, DHCP server, mail server, database server, application server, authentication server.
  • Dapat berupa server fisik atau virtual (lihat 1.12).

1.1.h PoE (Power over Ethernet)

  • Menyalurkan daya listrik melalui kabel Ethernet (twisted pair) bersamaan dengan data.
  • PSE (Power Sourcing Equipment): pemberi daya (mis. switch PoE).
  • PD (Powered Device): penerima daya (mis. AP, IP phone, kamera IP).

1.2.a Two-Tier (Collapsed Core)

  • Dua lapisan: Access dan Distribution/Core (collapsed).
  • Fungsi distribution dan core digabung dalam satu lapisan.
  • Cocok untuk kampus/gedung kecil-menengah; biaya lebih rendah, desain lebih sederhana, skalabilitas terbatas.
        [ Collapsed Core / Distribution ]
            /         |          \
      [Access]    [Access]     [Access]

1.2.b Three-Tier

Layer Fungsi
Access Menghubungkan endpoint (PC, AP, phone); PoE, VLAN, port security
Distribution Agregasi access switch; batas Layer 2/Layer 3; inter-VLAN routing, kebijakan (ACL, QoS), redundansi
Core Backbone berkecepatan tinggi; forwarding cepat, high availability; tanpa kebijakan yang memperlambat
  • Cocok untuk jaringan kampus besar yang membutuhkan skalabilitas dan ketersediaan tinggi.

1.2.c Spine-Leaf

  • Umum pada data center.
  • Leaf: switch tempat server/endpoint terhubung. Spine: backbone yang menghubungkan semua leaf.
  • Setiap leaf terhubung ke setiap spine; leaf tidak terhubung ke leaf, spine tidak terhubung ke spine.
  • Karakteristik: latensi dapat diprediksi (jumlah hop konsisten), optimal untuk traffic east-west (server ke server), mudah diskalakan dengan menambah leaf/spine.
   [Spine1]     [Spine2]
    /  |  \      /  |  \
 [Leaf1][Leaf2][Leaf3][Leaf4]   (setiap leaf ke setiap spine)

1.2.d WAN (Wide Area Network)

  • Menghubungkan LAN yang terpisah secara geografis (kantor cabang, kantor pusat, data center).
  • Umumnya disediakan oleh service provider (ISP).
  • Contoh konektivitas: leased line, MPLS, Metro Ethernet, dan koneksi Internet + VPN (broadband/DSL/kabel/seluler).

1.2.e Small Office/Home Office (SOHO)

  • Jaringan skala kecil (beberapa perangkat).
  • Biasanya memakai satu perangkat all-in-one (router + switch + AP + firewall dasar) yang terhubung ke ISP.
  • Sederhana, murah, manajemen minimal.

Duplex mismatch

  • Terjadi bila satu sisi full-duplex dan sisi lain half-duplex.
  • Gejala: kinerja lambat, late collisions pada sisi half-duplex, serta CRC/runt errors pada sisi full-duplex.
  • Penyebab umum: satu sisi di-hardcode, sisi lain auto-negotiation (negosiasi gagal, duplex default ke half pada 10/100).
  • Solusi: samakan pengaturan kedua sisi (keduanya auto, atau keduanya manual dengan nilai sama).

Speed mismatch

  • Kecepatan di kedua sisi berbeda → link tidak up atau tidak stabil.

Penyebab masalah kabel

  • Jenis kabel salah, kabel rusak/terlalu panjang (> 100 m untuk copper), konektor buruk, atau interferensi elektromagnetik (EMI).

1.6 Konfigurasi dan verifikasi IPv4 addressing dan subnetting

Materi yang diuji · CCNA 200-301 v1.1Domain 1.0 · Network Fundamentals · 20%Configure and verify

1.6 Configure and verify IPv4 addressing and subnetting

Struktur alamat IPv4

  • 32 bit, ditulis 4 oktet desimal (192.168.10.1).
  • Terdiri dari bagian network dan host, dibedakan oleh subnet mask (atau notasi CIDR /n).

Subnetting

Rumus:

  • Jumlah subnet = 2ⁿ (n = bit host yang dipinjam)
  • Jumlah host per subnet = 2ʰ − 2 (h = bit host tersisa; dikurangi alamat network dan broadcast)

Nilai bit per oktet: 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1

Tabel CIDR (oktet ke-4):

CIDR Subnet Mask Block size Host valid
/24 255.255.255.0 256 254
/25 255.255.255.128 128 126
/26 255.255.255.192 64 62
/27 255.255.255.224 32 30
/28 255.255.255.240 16 14
/29 255.255.255.248 8 6
/30 255.255.255.252 4 2

Contoh: 192.168.10.100/26

  1. Mask /26 = 255.255.255.192 → block size = 64.
  2. Subnet: .0, .64, .128, .192.
  3. .100 berada di subnet .64.
  4. Network ID: 192.168.10.64
  5. Broadcast: 192.168.10.127
  6. Range host: 192.168.10.65 – 192.168.10.126

Subnetting dengan mask berbeda-beda untuk tiap segmen (VLSM) mengikuti cara yang sama: pilih mask sesuai kebutuhan host tiap subnet.

Konfigurasi IPv4 pada interface

Router(config)# interface gigabitEthernet 0/0
Router(config-if)# ip address 192.168.10.1 255.255.255.0
Router(config-if)# no shutdown
Router(config-if)# description LAN-Marketing

Verifikasi

Router# show ip interface brief
Router# show interfaces gigabitEthernet 0/0
Router# show running-config interface gigabitEthernet 0/0
Router# ping 192.168.10.2

1.8 Konfigurasi dan verifikasi IPv6 addressing dan prefix

Materi yang diuji · CCNA 200-301 v1.1Domain 1.0 · Network Fundamentals · 20%Configure and verify

1.8 Configure and verify IPv6 addressing and prefix

Struktur alamat IPv6

  • 128 bit, ditulis 8 grup heksadesimal (16 bit per grup), dipisah titik dua.
  • Contoh: 2001:0DB8:0000:0000:0000:0000:0000:0001

Aturan penyingkatan:

  1. Hilangkan nol di depan pada tiap grup: 0DB8 → DB8, 0000 → 0.
  2. Ganti satu urutan grup nol berturut-turut dengan :: (hanya boleh sekali dalam satu alamat).
    • 2001:0DB8:0000:0000:0000:0000:0000:0001 → 2001:DB8::1

Prefix

  • Ditulis dengan notasi /panjang-prefix (contoh 2001:DB8:1::/64).
  • /64 adalah panjang prefix standar untuk subnet LAN (64 bit network/subnet + 64 bit interface ID).

Konfigurasi

Router(config)# ipv6 unicast-routing          ! aktifkan routing IPv6
Router(config)# interface gigabitEthernet 0/0

! Alamat statis penuh
Router(config-if)# ipv6 address 2001:DB8:1:1::1/64

! Interface ID otomatis dengan modified EUI-64
Router(config-if)# ipv6 address 2001:DB8:1:1::/64 eui-64

! Link-local manual
Router(config-if)# ipv6 address FE80::1 link-local

Router(config-if)# no shutdown

Verifikasi

Router# show ipv6 interface brief
Router# show ipv6 interface gigabitEthernet 0/0
Router# show ipv6 route
Router# ping 2001:DB8:1:1::2

  • 1.9.b Anycast
  • 1.9.c Multicast

1.9.a Unicast

Alamat untuk satu interface tunggal (komunikasi one-to-one).

Tipe Prefix Keterangan
Global Unicast 2000::/3 (awalan 2 atau 3) Dapat dirutekan di Internet; setara IPv4 publik
Unique Local FC00::/7 (praktiknya FD00::/8) Hanya untuk jaringan internal; tidak dirutekan di Internet; setara IPv4 privat
Link-Local FE80::/10 Hanya berlaku pada satu link/segmen; tidak dirutekan oleh router; otomatis dibuat di setiap interface IPv6

1.9.b Anycast

  • Satu alamat yang dipasang pada beberapa perangkat; paket dikirim ke perangkat terdekat (berdasarkan routing metric).
  • Dibuat dengan memasang alamat unicast yang sama pada lebih dari satu interface.

1.9.c Multicast

  • Dikirim ke sekelompok perangkat (one-to-many); prefix FF00::/8.
  • IPv6 tidak memakai broadcast; fungsinya digantikan multicast.
Alamat Fungsi
FF02::1 Semua node pada link (all-nodes)
FF02::2 Semua router pada link (all-routers)

1.9.d Modified EUI-64

Metode membentuk interface ID 64-bit dari MAC address 48-bit:

  1. Pecah MAC menjadi dua bagian (24 bit + 24 bit).
  2. Sisipkan FFFE di tengah.
  3. Balik bit ke-7 (bit U/L) dari byte pertama.

Contoh: MAC 00:1A:2B:3C:4D:5E

  1. 001A2B + FFFE + 3C4D5E → 001A:2BFF:FE3C:4D5E
  2. Byte pertama 00 = 0000 0000 → balik bit ke-7 → 0000 0010 = 02
  3. Interface ID = 021A:2BFF:FE3C:4D5E

Jika prefix 2001:DB8:1:1::/64, alamat lengkap: 2001:DB8:1:1:21A:2BFF:FE3C:4D5E.

Konsep Penjelasan

Server Virtualization

  • Satu server fisik menjalankan banyak Virtual Machine (VM), masing-masing dengan OS sendiri.

Containers

  • Virtualisasi pada level OS: container berbagi kernel OS host dan hanya membawa aplikasi + dependensinya.

VRFs (Virtual Routing and Forwarding)

  • Teknologi yang memungkinkan banyak routing table terpisah pada satu router fisik.
  • Setiap VRF seperti router virtual terpisah: isolasi traffic antar pelanggan/departemen dan mendukung alamat IP yang tumpang tindih.

1.13.a MAC Learning dan Aging

  • MAC learning: switch memeriksa source MAC address setiap frame yang masuk, lalu mencatatnya di MAC address table bersama port dan VLAN tempat frame diterima.
  • Aging: entri yang tidak aktif dihapus setelah waktu tertentu. Default pada Cisco switch: 300 detik (5 menit); timer di-reset setiap kali switch melihat frame dari MAC tersebut.

1.13.b Frame Switching

Keputusan forwarding berdasarkan destination MAC address:

Kondisi Tindakan
Known unicast (MAC tujuan ada di tabel) Teruskan hanya ke port tujuan
Unknown unicast (MAC tujuan tidak ada di tabel) Flood ke semua port dalam VLAN (kecuali port asal)
Broadcast / Multicast Flood ke semua port dalam VLAN (kecuali port asal)
Tujuan di port yang sama dengan asal Filter (frame dibuang)

1.13.c Frame Flooding

  • Pengiriman frame ke semua port dalam VLAN yang sama kecuali port tempat frame diterima.
  • Terjadi pada: unknown unicast, broadcast, dan multicast (tanpa pembatasan khusus).

1.13.d MAC Address Table

2.1 VLAN (normal range) yang melintasi beberapa switch

Materi yang diuji · CCNA 200-301 v1.1Domain 2.0 · Network Access · 20%Configure and verify

2.1 Configure and verify VLANs (normal range) spanning multiple switches

  • 2.1.a Access ports (data and voice)
  • 2.1.b Default VLAN
  • 2.1.c InterVLAN connectivity

Konsep VLAN

  • VLAN (Virtual LAN) membagi satu switch fisik menjadi beberapa broadcast domain logis yang terpisah.
  • Perangkat di VLAN berbeda tidak dapat saling berkomunikasi tanpa perangkat Layer 3.
  • Manfaat: memisahkan broadcast domain, meningkatkan keamanan, dan mengelompokkan perangkat secara logis (bukan fisik).
  • Normal range: VLAN ID 1 – 1005. VLAN 1 dan 1002 – 1005 dibuat otomatis dan tidak dapat dihapus. Informasi VLAN normal range disimpan di file vlan.dat pada flash.
  • VLAN dapat melintasi beberapa switch dengan menghubungkan switch menggunakan trunk (lihat 2.2) dan membuat VLAN yang sama di tiap switch.
  [SW1]============trunk============[SW2]
  VLAN10 ─ PC1                      PC3 ─ VLAN10   (satu subnet, satu VLAN, dua switch)
  VLAN20 ─ PC2                      PC4 ─ VLAN20

Membuat VLAN

Switch(config)# vlan 10
Switch(config-vlan)# name DATA
Switch(config-vlan)# exit
Switch(config)# vlan 20
Switch(config-vlan)# name VOICE

2.1.a Access Ports (data dan voice)

  • Access port hanya menjadi anggota satu VLAN (data) dan mengirim frame tanpa tag 802.1Q; dipakai untuk menghubungkan endpoint.
  • Voice VLAN: pada port yang tersambung ke IP phone (dengan PC dihubungkan di belakang phone), trafik suara dipisah ke VLAN tersendiri.
    • Trafik voice: dikirim dengan tag 802.1Q (voice VLAN).
    • Trafik data (dari PC): dikirim tanpa tag (access/data VLAN).
    • Switch memberi tahu phone voice VLAN-nya melalui CDP (atau LLDP).
Switch(config)# interface fastEthernet 0/1
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 10      ! data VLAN
Switch(config-if)# switchport voice vlan 20       ! voice VLAN

[PC] ──── [IP Phone] ──── Fa0/1 [Switch]
 data VLAN 10 (untagged)   voice VLAN 20 (tagged)

2.1.b Default VLAN

  • VLAN 1 adalah default VLAN: semua port switch berada di VLAN 1 secara default.
  • VLAN 1 tidak dapat dihapus, dan secara default juga menjadi native VLAN pada trunk.
  • Nama default: default.

2.1.c InterVLAN Connectivity

Perangkat di VLAN berbeda berada di subnet berbeda sehingga butuh routing antar VLAN.

Metode Keterangan
Router-on-a-Stick (ROAS) Satu link trunk antara switch dan router; router memakai subinterface per VLAN dengan encapsulation dot1Q
Layer 3 Switch (SVI) Switch L3 merutekan antar VLAN memakai SVI (Switch Virtual Interface) per VLAN; lebih cepat (hardware)

Router-on-a-Stick:

! Router
Router(config)# interface gigabitEthernet 0/0
Router(config-if)# no shutdown
Router(config)# interface gigabitEthernet 0/0.10
Router(config-subif)# encapsulation dot1Q 10
Router(config-subif)# ip address 192.168.10.1 255.255.255.0
Router(config)# interface gigabitEthernet 0/0.20
Router(config-subif)# encapsulation dot1Q 20
Router(config-subif)# ip address 192.168.20.1 255.255.255.0

! Switch (sisi router = trunk)
Switch(config)# interface gigabitEthernet 0/1
Switch(config-if)# switchport mode trunk

Switch(config)# interface vlan 10
Switch(config-if)# ip address 192.168.10.1 255.255.255.0
Switch(config-if)# no shutdown
Switch(config)# interface vlan 20
Switch(config-if)# ip address 192.168.20.1 255.255.255.0

2.5 Operasi dasar Rapid PVST+ Spanning Tree Protocol

Materi yang diuji · CCNA 200-301 v1.1Domain 2.0 · Network Access · 20%Interpret

2.5 Interpret basic operations of Rapid PVST+ Spanning Tree Protocol

  • 2.5.a Root port, root bridge (primary/secondary), and other port names
  • 2.5.b Port states and roles
  • 2.5.c PortFast
  • 2.5.d Root guard, loop guard, BPDU filter, and BPDU guard

Tujuan STP

Mencegah loop Layer 2 pada topologi redundan yang dapat menyebabkan broadcast storm, MAC table instability, dan duplikasi frame. STP memblokir sebagian port secara logis sehingga topologi menjadi tanpa loop (tree).

Rapid PVST+

  • Versi Cisco dari RSTP (IEEE 802.1w) yang berjalan per VLAN (satu instance STP per VLAN).
  • Konvergensi jauh lebih cepat dibanding STP/PVST+ klasik.
  • Antar switch bertukar BPDU (Bridge Protocol Data Unit); hello timer = 2 detik. RSTP menganggap neighbor hilang setelah 3 hello terlewat.
Switch(config)# spanning-tree mode rapid-pvst

2.5.a Root port, root bridge (primary/secondary), dan nama port lainnya

Bridge ID (BID) = Priority (default 32768) + System ID Extension (VLAN ID) + MAC address.

  • Contoh: VLAN 10, priority default → 32768 + 10 = 32778.
  • Priority berkelipatan 4096.

Pemilihan root bridge: switch dengan BID terendah (priority terendah; jika sama, MAC terendah).

Switch(config)# spanning-tree vlan 10 root primary      ! jadikan root (priority 24576 atau lebih rendah)
Switch(config)# spanning-tree vlan 10 root secondary    ! cadangan root (priority 28672)
Switch(config)# spanning-tree vlan 10 priority 4096     ! set manual

Root port (RP): satu per non-root switch; port dengan jalur terbaik menuju root bridge. Kriteria berurutan:

  1. Root path cost terendah
  2. Bridge ID pengirim (neighbor) terendah
  3. Port ID pengirim terendah

Designated port (DP): port yang meneruskan BPDU terbaik pada tiap segmen; satu DP per segmen. Semua port di root bridge adalah DP.

Default cost (short method):

Kecepatan Cost
10 Mbps 100
100 Mbps 19
1 Gbps 4
10 Gbps 2

Root path cost = penjumlahan cost interface yang menerima BPDU sepanjang jalur menuju root.

2.5.d Root guard, loop guard, BPDU filter, dan BPDU guard

Fitur Fungsi Perilaku saat terpicu Konfigurasi
BPDU Guard Melindungi port PortFast dari switch/BPDU yang tidak seharusnya Port masuk err-disabled (shutdown) saat menerima BPDU spanning-tree bpduguard enable (interface) atau spanning-tree portfast bpduguard default (global)
BPDU Filter Menghentikan pengiriman dan penerimaan BPDU pada port Port tidak lagi mengirim/menerima BPDU (berisiko loop jika salah pakai) spanning-tree bpdufilter enable (interface) atau spanning-tree portfast bpdufilter default (global)
Root Guard Menjaga posisi root bridge agar tidak digeser switch lain Menerima BPDU lebih superior → port menjadi root-inconsistent (diblokir); pulih otomatis jika BPDU superior berhenti spanning-tree guard root (interface, pada designated port)
Loop Guard Mencegah loop akibat hilangnya BPDU (mis. link unidirectional) Port non-designated tidak berubah menjadi designated/forwarding; menjadi loop-inconsistent spanning-tree guard loop (interface) atau spanning-tree loopguard default (global)

Catatan:

  • BPDU Guard biasanya dipasangkan dengan PortFast. Untuk memulihkan port err-disabled: shutdown lalu no shutdown, atau errdisable recovery cause bpduguard.
  • BPDU Filter pada level interface mengabaikan semua BPDU; pada level global (portfast default) filter dimatikan otomatis bila port menerima BPDU.
  • Root Guard dipasang pada port yang menghadap switch yang tidak boleh menjadi root.

3.1 Komponen routing table

Materi yang diuji · CCNA 200-301 v1.1Domain 3.0 · IP Connectivity · 25%Interpret

3.1 Interpret the components of routing table

  • 3.1.a Routing protocol code
  • 3.1.b Prefix
  • 3.1.c Network mask
  • 3.1.d Next hop
  • 3.1.e Administrative distance
  • 3.1.f Metric
  • 3.1.g Gateway of last resort

Routing table adalah tabel pada router yang berisi rute menuju jaringan tujuan. Dilihat dengan:

Router# show ip route
Router# show ipv6 route

Contoh output (IPv4):

Codes: L - local, C - connected, S - static, R - RIP, B - BGP
       D - EIGRP, O - OSPF, IA - OSPF inter area, * - candidate default

Gateway of last resort is 203.0.113.2 to network 0.0.0.0

S*    0.0.0.0/0 [1/0] via 203.0.113.2
      10.0.0.0/8 is variably subnetted, 4 subnets, 2 masks

L        10.1.1.1/32 is directly connected, GigabitEthernet0/0
O        10.2.2.0/24 [110/2] via 10.1.1.2, 00:05:12, GigabitEthernet0/0
S        10.3.3.0/24 [1/0] via 10.1.1.3

Cara membaca satu baris rute:

O   10.2.2.0/24  [110/2]  via 10.1.1.2,  00:05:12,  GigabitEthernet0/0
│   │      │       │   │      │            │              └─ Exit interface
│   │      │       │   │      │            └─ Umur rute (route timer)
│   │      │       │   │      └─ Next hop
│   │      │       │   └─ Metric
│   │      │       └─ Administrative distance
│   │      └─ Network mask (prefix length)
│   └─ Prefix (network address)
└─ Routing protocol code

3.1.a Routing protocol code

Kode di kolom paling kiri yang menunjukkan sumber/asal rute.

Kode Arti
L Local — alamat IP interface router itu sendiri (/32 untuk IPv4, /128 untuk IPv6)
C Connected — jaringan yang terhubung langsung ke interface
S Static — rute statis yang dikonfigurasi manual
S* Static yang menjadi candidate default route
O OSPF (IA = inter area)
D EIGRP
R RIP
B BGP

3.1.b Prefix

  • Alamat network tujuan (bagian network dari alamat), mis. 10.2.2.0.
  • Bersama panjang prefix membentuk jaringan tujuan yang dicocokkan dengan alamat IP tujuan paket.

3.1.c Network mask

  • Menentukan berapa bit dari alamat yang dianggap bagian network.
  • Ditampilkan dalam notasi prefix length (/24 = 255.255.255.0).
  • Baris seperti "10.0.0.0/8 is variably subnetted, 4 subnets, 2 masks" berarti ada beberapa subnet dari satu major network dengan panjang mask berbeda.

3.1.d Next hop

  • Alamat IP router berikutnya (via 10.1.1.2) yang harus dituju untuk mencapai jaringan tersebut.
  • Rute connected tidak memiliki next hop; hanya menampilkan exit interface (directly connected).

3.1.e Administrative distance (AD)

  • Ukuran tingkat kepercayaan sumber rute; makin kecil makin dipercaya.
  • Digunakan untuk memilih antara rute ke prefix yang sama dari sumber berbeda.
Sumber rute AD default
Connected 0
Static 1
eBGP 20
EIGRP (internal) 90
OSPF 110
RIP 120

3.1.f Metric

  • Nilai yang dipakai protokol routing untuk memilih jalur terbaik ke tujuan yang sama; makin kecil makin baik.
  • Setiap protokol memiliki cara hitung berbeda:
Protokol Metric
OSPF Cost = reference bandwidth ÷ bandwidth interface (reference default 100 Mbps; akumulasi sepanjang jalur)
Static / Connected Metric 0
  • Metric tidak dapat dibandingkan antar protokol yang berbeda.

3.1.g Gateway of last resort

  • Default route yang dipakai bila tidak ada rute lain yang cocok dengan tujuan paket.
  • Tampil sebagai: Gateway of last resort is 203.0.113.2 to network 0.0.0.0.
  • Jika belum ada default route: Gateway of last resort is not set.
  • Rute default ditandai * (mis. S*), yaitu 0.0.0.0/0 (IPv4) atau ::/0 (IPv6).

3.2 Keputusan forwarding router secara default

Materi yang diuji · CCNA 200-301 v1.1Domain 3.0 · IP Connectivity · 25%Determine

3.2 Determine how a router makes a forwarding decision by default

  • 3.2.a Longest prefix match
  • 3.2.b Administrative distance
  • 3.2.c Routing protocol metric

Saat paket tiba, router mencari rute terbaik di routing table dengan urutan berikut:

Urutan Kriteria Penjelasan
1 Longest prefix match Pilih rute dengan prefix length terpanjang (paling spesifik) yang cocok dengan IP tujuan
2 Administrative distance Jika ada beberapa sumber untuk prefix yang sama, pilih AD terendah
3 Routing protocol metric Jika sumber/protokol sama dan prefix sama, pilih metric terendah

3.2.a Longest prefix match

Contoh: paket ke 192.168.1.130 dengan rute berikut:

Rute di tabel Cocok? Panjang prefix
192.168.0.0/16 Ya 16
192.168.1.0/24 Ya 24
192.168.1.128/25 (range .128–.255) Ya 25 ← dipilih
0.0.0.0/0 Ya 0
192.168.1.0/25 (range .0–.127) Tidak –

Rute /25 dipilih karena paling spesifik. Default route /0 adalah pilihan terakhir.

3.2.b Administrative distance

  • Berlaku saat prefix dan prefix length sama, tetapi dipelajari dari sumber berbeda.
  • Contoh: 10.5.0.0/24 diketahui dari OSPF (AD 110) dan static (AD 1) → rute static dipasang di routing table.

3.2.c Routing protocol metric

  • Berlaku saat prefix sama dari protokol routing yang sama.
  • Contoh: dua jalur OSPF ke 10.5.0.0/24, cost 20 dan cost 30 → dipilih cost 20.
  • Jika metric sama (equal-cost), router dapat membagi trafik ke beberapa jalur (load balancing / ECMP).

Jika tidak ada rute yang cocok

  • Router memakai default route (gateway of last resort) bila ada.
  • Jika tidak ada, paket dibuang (drop) dan router biasanya mengirim pesan ICMP destination unreachable.

3.3 Static routing IPv4 dan IPv6

Materi yang diuji · CCNA 200-301 v1.1Domain 3.0 · IP Connectivity · 25%Configure and verify

3.3 Configure and verify IPv4 and IPv6 static routing

  • 3.3.a Default route
  • 3.3.b Network route
  • 3.3.c Host route
  • 3.3.d Floating static

Static route adalah rute yang dikonfigurasi manual oleh administrator.

  • Kelebihan: sederhana, tanpa overhead protokol routing, AD rendah (1).
  • Kekurangan: tidak beradaptasi otomatis terhadap perubahan topologi; sulit diskalakan.

Sintaks

! IPv4
Router(config)# ip route <prefix> <mask> {<next-hop> | <exit-interface> | <exit-interface> <next-hop>} [AD]

! IPv6 (aktifkan routing IPv6 terlebih dahulu)
Router(config)# ipv6 unicast-routing
Router(config)# ipv6 route <prefix>/<length> {<next-hop> | <exit-interface> | <exit-interface> <next-hop>} [AD]

Pilihan penentuan tujuan:

Bentuk Keterangan
Next-hop IP Router mencari exit interface melalui recursive lookup
Exit interface Cocok untuk link point-to-point; pada Ethernet kurang efisien
Fully specified (interface + next hop) Paling presisi; wajib untuk IPv6 bila next hop berupa alamat link-local

3.3.a Default Route

Mengarahkan semua trafik yang tidak punya rute spesifik; dipakai mis. untuk arah ke ISP/Internet.

! IPv4
Router(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1

! IPv6
Router(config)# ipv6 route ::/0 2001:DB8:FF::1

3.3.b Network Route

Rute ke seluruh jaringan/subnet tertentu.

! IPv4
Router(config)# ip route 192.168.20.0 255.255.255.0 10.1.1.2

! IPv6
Router(config)# ipv6 route 2001:DB8:20::/64 2001:DB8:12::2

! IPv6 dengan next hop link-local (wajib sertakan exit interface)
Router(config)# ipv6 route 2001:DB8:20::/64 gigabitEthernet 0/0 FE80::2

3.3.c Host Route

Rute ke satu host spesifik: IPv4 mask /32 (255.255.255.255), IPv6 /128.

! IPv4
Router(config)# ip route 192.168.100.5 255.255.255.255 10.1.1.2

! IPv6
Router(config)# ipv6 route 2001:DB8:100::5/128 2001:DB8:12::2

3.3.d Floating Static

  • Rute statis cadangan (backup) dengan AD lebih tinggi daripada rute utama.
  • Tidak dipasang di routing table selama rute utama aktif; baru dipakai saat rute utama hilang.
! Rute utama: static via ISP-A (AD 1); cadangan via ISP-B dengan AD 5
Router(config)# ip route 0.0.0.0 0.0.0.0 203.0.113.1
Router(config)# ip route 0.0.0.0 0.0.0.0 198.51.100.1 5

! Backup untuk rute yang dipelajari OSPF (AD 110) → pakai AD > 110
Router(config)# ip route 192.168.50.0 255.255.255.0 203.0.113.6 130

! IPv6
Router(config)# ipv6 route 2001:DB8:50::/64 2001:DB8:FF::2 130

Syarat: AD floating static harus lebih besar dari AD rute utama.

Router# show ip route static
Router# show ipv6 route static
Router# show running-config | include ip route
Router# ping 192.168.20.1
Router# traceroute 192.168.20.1

3.4 Single area OSPFv2

Materi yang diuji · CCNA 200-301 v1.1Domain 3.0 · IP Connectivity · 25%Configure and verify

3.4 Configure and verify single area OSPFv2

  • 3.4.a Neighbor adjacencies
  • 3.4.b Point-to-point
  • 3.4.c Broadcast (DR/BDR selection)
  • 3.4.d Router ID

Konsep dasar

  • OSPF (Open Shortest Path First): protokol routing link-state untuk IPv4 (OSPFv2), standar terbuka, AD 110, metric cost.
  • Setiap router membangun LSDB (Link-State Database) yang sama, lalu menjalankan algoritma SPF (Dijkstra) untuk menghitung jalur terbaik.
  • Single area: seluruh router berada pada satu area, yaitu Area 0 (backbone).
  • Berjalan langsung di atas IP (protocol number 89) dengan alamat multicast:
    • 224.0.0.5 — semua router OSPF
    • 224.0.0.6 — DR dan BDR

3.4.a Neighbor adjacencies

Tahapan terbentuknya adjacency:

State Keterangan
Down Belum ada Hello dari neighbor
Init Hello diterima, tetapi router sendiri belum terlihat di Hello neighbor
2-Way Komunikasi dua arah; Router ID saling terlihat (DR/BDR dipilih pada tahap ini di jaringan broadcast)
ExStart Menentukan master/slave untuk pertukaran database
Exchange Bertukar ringkasan database (DBD)
Loading Meminta (LSR) dan menerima (LSU) LSA yang belum dimiliki
Full Database tersinkron; adjacency penuh

Syarat agar dua router menjadi neighbor (parameter yang harus cocok/benar):

  • Berada pada area yang sama
  • Subnet dan mask yang sama pada link
  • Hello dan dead timer sama (default 10 s / 40 s pada broadcast & point-to-point)
  • Router ID unik (tidak boleh sama)
  • Authentication (bila dipakai) cocok
  • MTU dan tipe area yang kompatibel

3.4.b Point-to-point

  • Link yang menghubungkan tepat dua router (mis. link serial atau Ethernet yang dikonfigurasi point-to-point).
  • Tidak ada pemilihan DR/BDR; kedua router langsung membentuk adjacency Full.
  • Konvergensi lebih sederhana dan cepat.
Router(config-if)# ip ospf network point-to-point

3.4.c Broadcast (DR/BDR selection)

  • Network type default pada interface Ethernet adalah broadcast (multi-access).
  • Untuk mengurangi jumlah adjacency dan trafik LSA, dipilih:
    • DR (Designated Router) — pusat pertukaran LSA pada segmen
    • BDR (Backup Designated Router) — cadangan DR
    • DROther — router lainnya

Aturan pemilihan DR/BDR (per segmen):

  1. OSPF priority tertinggi (default 1; nilai 0 = tidak pernah menjadi DR/BDR).
  2. Jika seri, Router ID tertinggi.
  3. Non-preemptive: DR/BDR yang sudah terpilih tidak digantikan meski ada router baru dengan priority lebih tinggi (kecuali proses OSPF di-reset).

Hubungan adjacency:

Pasangan State
DROther ↔ DR / BDR Full
DROther ↔ DROther 2-Way 
Router(config-if)# ip ospf priority 100     ! naikkan peluang menjadi DR
Router(config-if)# ip ospf priority 0       ! tidak ikut pemilihan DR/BDR

3.4.d Router ID

  • Identitas unik router OSPF berformat 32 bit (ditulis seperti alamat IPv4, mis. 1.1.1.1).

Urutan pemilihan Router ID:

  1. Dikonfigurasi manual dengan perintah router-id
  2. Jika tidak ada → alamat IP loopback tertinggi yang aktif
  3. Jika tidak ada loopback → alamat IP interface fisik aktif tertinggi
  • Perubahan Router ID baru berlaku setelah clear ip ospf process atau reload.

Konfigurasi OSPFv2 (single area)

Metode 1 — perintah network:

Router(config)# router ospf 1                          ! process ID (lokal, tidak harus sama)
Router(config-router)# router-id 1.1.1.1
Router(config-router)# network 10.1.1.0 0.0.0.255 area 0
Router(config-router)# network 192.168.10.0 0.0.0.255 area 0
Router(config-router)# passive-interface gigabitEthernet 0/1   ! tidak mengirim Hello (mis. ke LAN pengguna)

Metode 2 — langsung pada interface:

Router(config)# interface gigabitEthernet 0/0
Router(config-if)# ip ospf 1 area 0

Prefix Subnet mask Wildcard mask
/24 255.255.255.0 0.0.0.255
/30 255.255.255.252 0.0.0.3
/32 (host) 255.255.255.255 0.0.0.0

4.1 Inside source NAT (static dan pool)

Materi yang diuji · CCNA 200-301 v1.1Domain 4.0 · IP Services · 10%Configure and verify

4.1 Configure and verify inside source NAT using static and pools

Konsep

  • NAT (Network Address Translation) menerjemahkan alamat IP pada header paket, umumnya dari alamat privat (inside) ke alamat publik (outside) agar perangkat internal dapat mengakses Internet.
  • Inside source NAT: yang diterjemahkan adalah alamat sumber dari host di dalam jaringan (paket keluar).
  • Manfaat: menghemat alamat IPv4 publik dan menyembunyikan alamat internal.

Terminologi alamat NAT

Istilah Arti
Inside local Alamat host inside sebagaimana terlihat dari jaringan inside (biasanya IP privat)
Inside global Alamat host inside sebagaimana terlihat dari jaringan luar (IP publik hasil terjemahan)
Outside local Alamat host outside sebagaimana terlihat dari jaringan inside
Outside global Alamat sebenarnya dari host outside pada jaringan luar 
[PC 192.168.1.10] ──Gi0/0 (inside) [Router NAT] Gi0/1 (outside)── Internet
 inside local = 192.168.1.10   →   inside global = 203.0.113.10

Jenis inside source NAT

Jenis Pemetaan Keterangan
Static NAT 1:1 permanen Satu inside local selalu ↔ satu inside global; cocok untuk server yang harus dapat diakses dari luar
Dynamic NAT (pool) 1:1 sementara Alamat inside global diambil dari pool; jika pool habis, host lain tidak dapat diterjemahkan

Konfigurasi

Langkah wajib: tentukan interface inside dan outside.

Router(config)# interface gigabitEthernet 0/0
Router(config-if)# ip nat inside
Router(config)# interface gigabitEthernet 0/1
Router(config-if)# ip nat outside

1) Static NAT:

Router(config)# ip nat inside source static 192.168.1.10 203.0.113.10

2) Dynamic NAT dengan pool:

Router(config)# ip nat pool PUBLIC 203.0.113.10 203.0.113.20 netmask 255.255.255.0
Router(config)# access-list 1 permit 192.168.1.0 0.0.0.255          ! host inside yang boleh di-NAT
Router(config)# ip nat inside source list 1 pool PUBLIC

Verifikasi

Router# show ip nat translations
Router# show ip nat statistics
Router# clear ip nat translation *

Contoh show ip nat translations:

Pro  Inside global        Inside local        Outside local      Outside global
---  203.0.113.10         192.168.1.10        ---                ---

4.3 Peran DHCP dan DNS dalam jaringan

Materi yang diuji · CCNA 200-301 v1.1Domain 4.0 · IP Services · 10%Explain

4.3 Explain the role of DHCP and DNS within the network

DHCP (Dynamic Host Configuration Protocol)

Peran: memberikan konfigurasi IP otomatis kepada client sehingga tidak perlu diatur manual.

Parameter yang diberikan: alamat IP, subnet mask, default gateway, DNS server, dan lease time.

Manfaat: manajemen terpusat, mengurangi kesalahan konfigurasi dan konflik IP.

  • Port: UDP 67 (server) dan UDP 68 (client).

Proses DORA:

Langkah Pesan Arah Keterangan
1 Discover Client → broadcast Client mencari server DHCP
2 Offer Server → client Server menawarkan konfigurasi IP
3 Request Client → server (broadcast) Client meminta/menerima penawaran
4 Acknowledge Server → client Server mengonfirmasi dan memberi lease
  • Lease: alamat dipinjamkan untuk jangka waktu tertentu dan dapat diperbarui (renew) sebelum habis (pada ±50% masa lease).

DNS (Domain Name System)

Peran: menerjemahkan nama domain (mis. www.example.com) menjadi alamat IP, sehingga pengguna tidak perlu menghafal alamat IP.

  • Port: UDP/TCP 53.
  • Struktur hierarkis dan terdistribusi (root → TLD → domain otoritatif).
  • Alamat DNS server biasanya diterima client melalui DHCP.
  • Resolver menyimpan hasil query dalam cache untuk mempercepat permintaan berikutnya.

Alur singkat:

Client ──(1) query "www.example.com"──▶ DNS Server
Client ◀──(2) jawaban: 93.184.216.34 ──── DNS Server
Client ──(3) kirim trafik ke 93.184.216.34

4.7 Forwarding per-hop behavior (PHB) untuk QoS

Materi yang diuji · CCNA 200-301 v1.1Domain 4.0 · IP Services · 10%Explain

4.7 Explain the forwarding per-hop behavior (PHB) for QoS such as classification, marking, queuing, congestion, policing, and shaping

Tujuan QoS

QoS (Quality of Service) mengatur perlakuan terhadap jenis trafik berbeda agar trafik penting (mis. voice) mendapat layanan lebih baik saat jaringan padat.

Karakteristik yang dikelola:

Karakteristik Arti
Bandwidth Kapasitas link
Delay Waktu tempuh paket
Jitter Variasi delay antar paket
Loss Persentase paket hilang

Contoh kebutuhan voice (satu arah): delay ≤ 150 ms, jitter ≤ 30 ms, loss ≤ 1%.

Per-Hop Behavior (PHB)

  • PHB adalah perlakuan forwarding yang diterapkan setiap router (hop) secara independen terhadap paket, berdasarkan marking pada paket (model DiffServ).
  • Tiap hop menerapkan alur: classification → marking → queuing → congestion management/avoidance → policing/shaping.

Classification

Mengidentifikasi jenis trafik dan mengelompokkannya ke dalam kelas.

  • Berdasarkan: ACL (IP/port), NBAR (aplikasi), interface masuk, atau marking yang sudah ada (CoS/DSCP).

Marking

Memberi label prioritas pada paket agar hop berikutnya dapat mengenali kelasnya tanpa mengklasifikasi ulang.

Layer Field Keterangan
Layer 2 CoS (field PCP pada tag 802.1Q) 3 bit, nilai 0 – 7
Layer 3 IP Precedence 3 bit pada byte ToS (0 – 7)
Layer 3 DSCP 6 bit pada byte ToS/DS (0 – 63)

Nilai DSCP/PHB umum:

PHB DSCP Penggunaan
Default / Best Effort (BE) 0 Trafik biasa
EF (Expedited Forwarding) 46 Voice — prioritas tertinggi, delay/jitter/loss rendah
AFxy (Assured Forwarding) AF11=10, AF21=18, AF31=26, AF41=34 x = kelas (1–4), y = drop precedence (1–3; makin besar makin mudah dibuang). DSCP = 8x + 2y
CS (Class Selector) CS1=8 … CS6=48, CS7=56 Kompatibel dengan IP Precedence

Trust boundary: titik di jaringan tempat marking dari perangkat ujung mulai dipercaya (mis. IP phone), atau di-re-mark oleh switch/router.

Queuing

  • Saat link padat, paket menunggu di antrean (queue); scheduler menentukan paket mana yang dikirim lebih dulu.
  • Contoh mekanisme: FIFO (default, tanpa prioritas), CBWFQ (Class-Based Weighted Fair Queuing: bandwidth minimum per kelas), LLQ (Low Latency Queuing: CBWFQ + antrean prioritas ketat untuk voice).

Congestion (management dan avoidance)

  • Congestion management: pengelolaan saat antrean penuh melalui queuing (di atas).
  • Congestion avoidance: mencegah antrean penuh dengan membuang paket lebih awal.
    • Tail drop: paket baru dibuang saat antrean penuh (semua kelas terdampak).
    • RED / WRED ((Weighted) Random Early Detection): membuang paket secara acak sebelum antrean penuh; WRED memilih berdasarkan marking (paket prioritas rendah dibuang lebih dulu), mengurangi sinkronisasi TCP.

Policing dan Shaping

Keduanya membatasi laju trafik terhadap batas tertentu (mis. CIR), tetapi memperlakukan kelebihan trafik secara berbeda.

Aspek Policing Shaping
Kelebihan trafik Dibuang atau di-re-mark Ditahan (buffer) lalu dikirim saat ada kapasitas
Delay Tidak menambah delay Menambah delay (buffering)
Efek pada trafik Trafik tampak bergerigi/bursty Trafik lebih halus (smoothing)
Arah penerapan Inbound dan outbound Outbound saja
Contoh penggunaan Membatasi trafik dari pelanggan/ISP Menyesuaikan laju kirim dengan CIR link WAN

5.5 Describe IPsec remote access and site-to-site VPNs

Konsep VPN

VPN (Virtual Private Network) membuat terowongan (tunnel) terenkripsi melintasi jaringan yang tidak tepercaya (mis. Internet) sehingga data tetap rahasia, utuh, dan terautentikasi.

Jenis VPN

Aspek Site-to-Site VPN Remote Access VPN
Menghubungkan Dua jaringan/lokasi (kantor pusat ↔ cabang) Satu pengguna/perangkat ↔ jaringan perusahaan

Bagi pengguna Transparan (host tidak menjalankan software VPN) Pengguna menjalankan VPN client (mis. Cisco Secure Client/AnyConnect)

Layanan yang diberikan IPsec

Layanan Penjelasan Mekanisme
Confidentiality Data dienkripsi AES (disarankan), 3DES, DES (usang)

5.6 Access Control List (ACL)

Materi yang diuji · CCNA 200-301 v1.1Domain 5.0 · Security Fundamentals · 15%Configure and verify

5.6 Configure and verify access control lists

Konsep

  • ACL adalah daftar aturan permit/deny yang menyaring paket berdasarkan kriteria (alamat, protokol, port).
  • Diproses berurutan dari atas ke bawah; berhenti pada kecocokan pertama.
  • Di akhir ada implicit deny any — paket yang tidak cocok aturan mana pun dibuang.
  • Hanya satu ACL per protokol, per arah, per interface.
  • Arah: inbound (masuk interface) atau outbound (keluar interface).

Jenis ACL

Aspek Standard ACL Extended ACL
Nomor 1–99, 1300–1999 100–199, 2000–2699
Kriteria Hanya alamat IP sumber Protokol, sumber, tujuan, dan port
Penempatan Dekat tujuan Dekat sumber
Bentuk Numbered atau named Numbered atau named

Wildcard mask: kebalikan subnet mask (0 = harus cocok, 1 = diabaikan).

Keyword Arti
host 10.1.1.1 Sama dengan 10.1.1.1 0.0.0.0
any Sama dengan 0.0.0.0 255.255.255.255
192.168.1.0 0.0.0.255 Seluruh subnet 192.168.1.0/24

Konfigurasi

Standard ACL:

! Numbered
Router(config)# access-list 10 permit 192.168.1.0 0.0.0.255

! Named
Router(config)# ip access-list standard BLOCK_HOST
Router(config-std-nacl)# deny host 192.168.1.50
Router(config-std-nacl)# permit any

Extended ACL:

! Sintaks: permit|deny <protokol> <sumber> <wildcard> [operator port] <tujuan> <wildcard> [operator port]

Router(config)# ip access-list extended WEB_ONLY
Router(config-ext-nacl)# remark Izinkan web dari LAN
Router(config-ext-nacl)# permit tcp 192.168.1.0 0.0.0.255 any eq 80
Router(config-ext-nacl)# permit tcp 192.168.1.0 0.0.0.255 any eq 443
Router(config-ext-nacl)# deny ip any any log

! Numbered
Router(config)# access-list 110 permit tcp 192.168.1.0 0.0.0.255 host 10.1.1.10 eq 22

Operator port: eq (sama dengan), neq, gt, lt, range.

Menerapkan ACL:

! Pada interface
Router(config)# interface gigabitEthernet 0/0
Router(config-if)# ip access-group WEB_ONLY in      ! atau out

! Membatasi akses remote (VTY)
Router(config)# line vty 0 15
Router(config-line)# access-class 10 in

Mengedit named ACL (nomor urut):

Router(config)# ip access-list extended WEB_ONLY
Router(config-ext-nacl)# 15 permit tcp 192.168.1.0 0.0.0.255 any eq 8080   ! sisipkan pada urutan 15
Router(config-ext-nacl)# no 20                                             ! hapus entri urutan 20

Verifikasi

Router# show access-lists
Router# show ip access-lists WEB_ONLY
Router# show ip interface gigabitEthernet 0/0      ! menampilkan ACL inbound/outbound
Router# show running-config | section access-list
  • show access-lists menampilkan hit counter (matches) pada tiap entri.

5.7 Fitur keamanan Layer 2

Materi yang diuji · CCNA 200-301 v1.1Domain 5.0 · Security Fundamentals · 15%Configure and verify

5.7 Configure and verify Layer 2 security features (DHCP snooping, dynamic ARP inspection, and port security)

Melindungi dari serangan di jaringan LAN (pada switch).

DHCP Snooping

Fungsi: bertindak seperti "firewall" antara host yang tidak tepercaya dan server DHCP yang sah.

  • Mencegah rogue DHCP server (server DHCP palsu) dan membantu mitigasi DHCP starvation.
  • Port dibagi menjadi:
    • Trusted — port ke server DHCP sah / uplink (pesan DHCP server diizinkan).
    • Untrusted — port ke client (pesan DHCP server, mis. Offer/Ack, diblokir).
  • Membangun DHCP snooping binding table (MAC, IP, VLAN, port, lease) yang juga dipakai DAI.
Switch(config)# ip dhcp snooping
Switch(config)# ip dhcp snooping vlan 10,20

Switch(config)# interface gigabitEthernet 0/1          ! uplink / ke server DHCP
Switch(config-if)# ip dhcp snooping trust

Switch(config)# interface range fastEthernet 0/1 - 24  ! port client (untrusted, default)
Switch(config-if-range)# ip dhcp snooping limit rate 15

Switch# show ip dhcp snooping
Switch# show ip dhcp snooping binding

Dynamic ARP Inspection (DAI)

Fungsi: memvalidasi paket ARP agar tidak dipalsukan (ARP spoofing/poisoning, dasar serangan MITM).

  • Membandingkan pasangan IP–MAC pada ARP dengan DHCP snooping binding table (atau ARP ACL statis).
  • ARP tidak valid pada port untrusted → dibuang (dan dilog).
  • Port dibagi trusted (mis. uplink antar switch) dan untrusted (port client; default).
  • Bergantung pada DHCP snooping untuk tabel binding.
Switch(config)# ip arp inspection vlan 10,20

Switch(config)# interface gigabitEthernet 0/1         ! uplink
Switch(config-if)# ip arp inspection trust

Switch(config-if)# ip arp inspection limit rate 15    ! (opsional) batasi laju ARP pada port client

! Validasi tambahan (opsional)
Switch(config)# ip arp inspection validate src-mac dst-mac ip

Switch# show ip arp inspection
Switch# show ip arp inspection interfaces
Switch# show ip arp inspection vlan 10

Port Security

Fungsi: membatasi MAC address yang boleh memakai sebuah port, mencegah MAC flooding dan perangkat tidak sah.

  • Diterapkan pada port access (atau trunk statis), bukan pada port dinamis.
  • Jenis pembelajaran MAC: static, dynamic (hilang saat reload), dan sticky (dipelajari otomatis dan disimpan di running-config).
  • Default: maksimum 1 MAC, violation = shutdown.
Switch(config)# interface fastEthernet 0/1
Switch(config-if)# switchport mode access
Switch(config-if)# switchport port-security
Switch(config-if)# switchport port-security maximum 2
Switch(config-if)# switchport port-security mac-address 0050.7966.6800     ! static
Switch(config-if)# switchport port-security mac-address sticky              ! sticky
Switch(config-if)# switchport port-security violation shutdown              ! protect | restrict | shutdown

Mode violation:

Mode Frame pelanggar Log / SNMP trap Counter violation Port
Protect Dibuang Tidak Tidak bertambah Tetap up
Restrict Dibuang Ya Bertambah Tetap up
Shutdown (default) Port dimatikan Ya Bertambah err-disabled

Memulihkan port err-disabled:

Switch(config-if)# shutdown
Switch(config-if)# no shutdown
! atau otomatis:
Switch(config)# errdisable recovery cause psecure-violation

Verifikasi:

Switch# show port-security
Switch# show port-security interface fastEthernet 0/1
Switch# show port-security address
Switch# show interfaces status err-disabled

6.3 Arsitektur controller-based (software defined)

Materi yang diuji · CCNA 200-301 v1.1Domain 6.0 · Automation and Programmability · 10%Describe

6.3 Describe controller-based, software defined architecture (overlay, underlay, and fabric)

  • 6.3.a Separation of control plane and data plane
  • 6.3.b Northbound and Southbound APIs

Arsitektur Software-Defined Networking (SDN) memisahkan fungsi "otak" jaringan dari perangkat pengirim data, lalu mengelolanya secara terpusat. Komponen logis jaringan dibangun dari underlay, overlay, dan fabric.

Underlay

  • Jaringan fisik (switch, router, kabel) yang menyediakan konektivitas IP antar node fabric.
  • Biasanya Layer 3 (routed), sederhana, stabil, dan berkinerja tinggi.
  • Berfungsi sebagai transport bagi trafik overlay; tidak peduli pada layanan/segmentasi pengguna.

Overlay

  • Jaringan virtual yang dibangun di atas underlay menggunakan tunnel/enkapsulasi (mis. VXLAN, GRE, IPsec).
  • Memisahkan topologi logis dari topologi fisik: segmentasi, mobilitas, dan kebijakan dapat diatur tanpa mengubah underlay.
  • Paket pengguna dibungkus (encapsulated) dengan header baru melintasi underlay.

Fabric

  • Gabungan overlay + underlay yang berfungsi sebagai satu domain jaringan terpadu, dikelola controller sebagai satu entitas.
  • Contoh: Cisco SD-Access (fabric berbasis VXLAN yang dikelola Catalyst Center).
        ┌───────────────── FABRIC ─────────────────┐
        │  OVERLAY  (jaringan virtual/tunnel VXLAN) │
        │  ─────────────────────────────────────── │
        │  UNDERLAY (switch/router + routing IP)    │
        └───────────────────────────────────────────┘
Aspek Underlay Overlay
Sifat Fisik Logis/virtual
Fungsi Transport & konektivitas IP Layanan, segmentasi, kebijakan
Teknologi umum Routing IP (routed access) VXLAN, tunnel

6.3.a Separation of control plane and data plane

Plane Fungsi Contoh
Control plane ("otak") Mengambil keputusan: membangun tabel routing/forwarding Protokol routing (OSPF), STP, pembelajaran ARP/MAC
Data plane / forwarding plane ("otot") Meneruskan frame/paket sesuai tabel yang sudah dibangun Forwarding paket, enkapsulasi, NAT, ACL, marking QoS
  • Traditional: setiap perangkat menjalankan control plane dan data plane sendiri.
  • SDN/controller-based: control plane (logika/keputusan) dipusatkan pada controller, sedangkan data plane tetap pada perangkat jaringan yang bertugas meneruskan paket.
  • Manfaat: pandangan dan kebijakan terpusat, perubahan lebih cepat, jaringan dapat diprogram.

6.4 AI (generative dan predictive) dan machine learning dalam operasional jaringan

Materi yang diuji · CCNA 200-301 v1.1Domain 6.0 · Automation and Programmability · 10%Explain

6.4 Explain AI (generative and predictive) and machine learning in network operations

Konsep dasar

Istilah Penjelasan
AI (Artificial Intelligence) Sistem yang meniru kemampuan kognitif manusia (menganalisis, memutuskan, belajar)
ML (Machine Learning) Bagian dari AI: algoritma belajar dari data untuk menemukan pola dan membuat prediksi tanpa diprogram secara eksplisit

Pendekatan ML umum: supervised (data berlabel), unsupervised (menemukan pola tanpa label), dan reinforcement (belajar lewat umpan balik/reward).

Predictive AI

  • Menganalisis data historis dan real-time (telemetri, log, flow) menggunakan model ML untuk memprediksi atau mendeteksi kondisi.
  • Penggunaan dalam network operations:
    • Deteksi anomali dan penetapan baseline kinerja normal
    • Memprediksi kegagalan perangkat/link dan kebutuhan kapasitas (capacity planning)
    • Analisis akar masalah dan deteksi masalah secara proaktif
    • Deteksi ancaman keamanan (perilaku trafik tidak wajar)
  • Contoh: AI Network Analytics pada Cisco Catalyst Center.

Generative AI

  • Model (umumnya LLM, Large Language Model) yang menghasilkan konten baru: teks, kode, ringkasan, konfigurasi.
  • Penggunaan dalam network operations:
    • Asisten percakapan untuk bertanya dengan bahasa alami (mis. "mengapa aplikasi lambat di cabang A?")
    • Menghasilkan konfigurasi atau skrip otomasi (mis. playbook Ansible, template)
    • Merangkum log, insiden, dan data troubleshooting
    • Membuat dokumentasi dan memandu langkah troubleshooting
  • Catatan: keluaran dapat keliru (hallucination) → harus diverifikasi manusia sebelum diterapkan; perhatikan privasi data.

Perbandingan

Aspek Predictive AI Generative AI
Tujuan Memprediksi/mendeteksi kejadian Menciptakan konten baru
Keluaran Skor, prediksi, peringatan, klasifikasi Teks, kode, konfigurasi, ringkasan
Data masukan Data historis dan telemetri jaringan Prompt/pertanyaan + data konteks
Contoh di jaringan Prediksi kegagalan, deteksi anomali Chat asisten, pembuat konfigurasi/skrip

Manfaat dan pertimbangan

  • Manfaat: deteksi masalah lebih cepat, mengurangi waktu perbaikan (MTTR), operasi proaktif, mengurangi alert noise.
  • Pertimbangan: kualitas data, bias model, kemampuan menjelaskan hasil, dan perlunya pengawasan manusia.

6.5 Karakteristik REST-based API

Materi yang diuji · CCNA 200-301 v1.1Domain 6.0 · Automation and Programmability · 10%Describe

6.5 Describe characteristics of REST-based APIs (authentication types, CRUD, HTTP verbs, and data encoding)

Konsep

  • API (Application Programming Interface) memungkinkan satu perangkat lunak berkomunikasi dengan yang lain.
  • REST (Representational State Transfer) adalah gaya arsitektur API berbasis HTTP/HTTPS; API yang mengikutinya disebut RESTful.

Karakteristik utama REST:

Karakteristik Penjelasan
Client-server Client (pengirim permintaan) dan server (penyedia resource) terpisah
Stateless Tiap request berdiri sendiri; server tidak menyimpan state sesi antar request
Cacheable Respons dapat ditandai agar dapat di-cache
Uniform interface Resource diidentifikasi dengan URI dan dioperasikan lewat HTTP verb standar
Layered system Dapat melewati perantara (proxy, load balancer) tanpa diketahui client

Struktur request

https://api.example.com/v1/devices/R1?fields=hostname
└─┬─┘   └──────┬──────┘ └───── path/resource ─────┘ └─ query ─┘
Scheme       Host
  • Komponen request: HTTP verb, URI, header (mis. Authorization, Content-Type), dan body (data, untuk POST/PUT/PATCH).

CRUD dan HTTP verbs

Operasi CRUD HTTP verb Fungsi
Create POST Membuat resource baru
Read GET Mengambil/membaca resource
Update PUT Mengganti/memperbarui resource secara menyeluruh
Update PATCH Memperbarui sebagian resource
Delete DELETE Menghapus resource

Authentication types

Tipe Cara kerja
Basic authentication Username dan password dikirim di header Authorization (di-encode Base64, bukan dienkripsi) → wajib lewat HTTPS
Token-based (Bearer) Client login sekali, memperoleh token, lalu mengirimnya pada tiap request (mis. Authorization: Bearer <token>)
API key Kunci unik yang dikirim di header atau query string untuk mengidentifikasi aplikasi
OAuth 2.0 Kerangka otorisasi terdelegasi: aplikasi mendapat access token terbatas tanpa mengetahui password pengguna

Contoh pada Cisco Catalyst Center: client mengirim POST dengan Basic auth ke endpoint autentikasi untuk memperoleh token, lalu menyertakan token pada header X-Auth-Token di request berikutnya.

Data encoding

Format data yang dipertukarkan pada body request/response, ditandai dengan header Content-Type / Accept.

Format Ciri Header
JSON Ringkas, mudah dibaca, paling umum pada REST application/json
XML Berbasis tag, lebih verbose application/xml
YAML Berbasis indentasi, mudah dibaca manusia (umum pada file konfigurasi/otomasi) application/yaml

Data yang sama dalam tiga format:

JSON:  {"hostname": "R1", "enabled": true}

XML:   <device><hostname>R1</hostname><enabled>true</enabled></device>

YAML:  hostname: R1
       enabled: true

Contoh request dan response

GET https://api.example.com/v1/devices/R1
Authorization: Bearer eyJhbGciOi...
Accept: application/json

HTTP/1.1 200 OK
Content-Type: application/json

{ "hostname": "R1", "model": "ISR4331", "status": "up" }

6.6 Configuration management: Ansible dan Terraform

Materi yang diuji · CCNA 200-301 v1.1Domain 6.0 · Automation and Programmability · 10%Recognize

6.6 Recognize the capabilities of configuration management mechanisms such as Ansible and Terraform

Kemampuan umum configuration management

  • Mengelola konfigurasi banyak perangkat/infrastruktur secara otomatis dan konsisten.
  • Mendefinisikan kondisi yang diinginkan (desired state) dalam file/kode yang dapat disimpan di version control.
  • Idempotent: menjalankan berulang kali menghasilkan keadaan akhir yang sama (tidak menggandakan perubahan).
  • Mendeteksi dan memperbaiki configuration drift, serta mempercepat provisioning dan mengurangi kesalahan manual.

Ansible

Aspek Penjelasan
Pengembang Red Hat
Sifat Agentless — tidak perlu software agen di perangkat; terhubung via SSH, NETCONF, atau API
Model Push — control node mendorong konfigurasi ke perangkat
Bahasa YAML (file playbook)
Fungsi utama Manajemen konfigurasi, deployment, dan orkestrasi tugas

Komponen: control node (tempat Ansible dijalankan), managed nodes (perangkat target), inventory (daftar perangkat), playbook (rangkaian play), task, module (unit kerja, mis. modul ios_*), dan role.

Contoh playbook:

- name: Konfigurasi VLAN pada switch
  hosts: switches
  gather_facts: false
  tasks:
    - name: Pastikan VLAN 10 ada
      cisco.ios.ios_vlans:
        config:
          - vlan_id: 10
            name: DATA
        state: merged

Terraform

Aspek Penjelasan
Pengembang HashiCorp
Pendekatan Infrastructure as Code (IaC) — infrastruktur didefinisikan dalam kode
Sifat Declarative (menyatakan hasil akhir yang diinginkan) dan agentless (memakai API provider)
Bahasa HCL (HashiCorp Configuration Language)
Fungsi utama Provisioning infrastruktur (cloud, jaringan, server)
Komponen Provider (konektor ke platform/API), resource, dan state file (mencatat kondisi infrastruktur saat ini)

Alur kerja Terraform:

6.7 Komponen data JSON

Materi yang diuji · CCNA 200-301 v1.1Domain 6.0 · Automation and Programmability · 10%Recognize

6.7 Recognize components of JSON-encoded data

JSON (JavaScript Object Notation) adalah format data teks ringan, mudah dibaca, berbasis pasangan key–value; dipakai luas pada REST API dan otomasi jaringan.

Tipe data JSON

Tipe Contoh
String "GigabitEthernet0/1" (dalam tanda kutip ganda)
Number 1500, 3.14
Boolean true, false
Null null
Object { "key": "value" } — kumpulan pasangan key–value dalam kurung kurawal
Array [ "a", "b" ] — daftar nilai berurutan dalam kurung siku

Aturan sintaks

  • Data berupa pasangan "key": value; key harus berupa string dalam tanda kutip ganda.
  • Pasangan dipisahkan koma (tanpa koma setelah elemen terakhir).
  • Object memakai { }, array memakai [ ]; keduanya dapat bersarang (nested).
  • String menggunakan tanda kutip ganda (" "); JSON tidak mendukung komentar.
  • Spasi/indentasi tidak memengaruhi arti (hanya untuk keterbacaan).

Contoh dan penjelasan

{
  "interface": {
    "name": "GigabitEthernet0/1",
    "enabled": true,
    "mtu": 1500,
    "description": null,
    "ipv4": [
      { "address": "192.168.1.1", "mask": "255.255.255.0" },
      { "address": "192.168.2.1", "mask": "255.255.255.0" }
    ]
  }
}
Bagian Penjelasan
{ ... } terluar Object utama
"interface" Key yang nilainya berupa object bersarang
"name": "GigabitEthernet0/1" Pasangan key–value bertipe string
"enabled": true Nilai boolean
"mtu": 1500 Nilai number
"description": null Nilai null (kosong)
"ipv4": [ ... ] Array berisi dua object

Cara membaca/mengakses nilai (indeks array dimulai dari 0):

interface → ipv4 → elemen ke-0 → address   =   "192.168.1.1"
data["interface"]["ipv4"][0]["address"]
